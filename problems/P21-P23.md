# Problems P21–P23

## P21 — Employee Salary Percentile
**Concept:** PERCENTILE_CONT, threshold classification pattern

```sql
WITH CTE AS (
    SELECT DISTINCT
        PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY Salary) OVER () AS P25,
        PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY Salary) OVER () AS P75
    FROM Employees
)
SELECT EmpName, Salary,
    CASE
        WHEN Salary <= P25 THEN 'Bottom 25%'
        WHEN Salary >= P75 THEN 'Top 25%'
        ELSE 'Middle 50%'
    END AS Bucket
FROM Employees, CTE
ORDER BY Salary DESC
```

**Key learnings:**
- `PERCENTILE_CONT(0.25) OVER()` returns same value on every row — use `DISTINCT` to collapse to 1 row
- Cross join `FROM Employees, CTE` — 1-row CTE attaches threshold to every employee row
- `PERCENTILE_CONT` uses linear interpolation between rows (not just picks nearest)

**Pattern name: Threshold Classification**
> Compute threshold → cross join to data → classify with CASE
> Real use: grade curves, SLA tiers, risk scoring, percentile bands

**Performance finding:**
- 1 CTE (both P25+P75 together): SubTreeCost = 0.0416
- 3 CTEs (P25, P75, classify separate): SubTreeCost = 0.0679 — 63% more expensive
- Why: separate CTEs = separate sorts + separate spools. Combined = one shared pass.
- Rule: multiple percentiles from same column → keep in one CTE

## P22 — Department Performance Report
**Concept:** CTE + JOIN vs Window function — performance comparison

**Problem:** Per department: headcount, avg salary, name of highest paid employee.

### Approach 1 — CTE + JOIN (WINNER: cost 0.0149)
```sql
WITH CTE AS (
    SELECT
        DeptID,
        COUNT(1) AS HeadCount,
        AVG(CAST(Salary AS DECIMAL(10,2))) AS AvgSalary,
        MAX(Salary) AS MaxSalary
    FROM Employees
    GROUP BY DeptID
)
SELECT emp.Department, cte.HeadCount,
    CAST(cte.AvgSalary AS DECIMAL(10,2)) AS AvgSalary,
    emp.EmpName AS TopEarner
FROM CTE
INNER JOIN Employees emp
    ON emp.Salary = cte.MaxSalary
    AND emp.DeptID = cte.DeptID   -- MUST join on both value AND scope
```

### Approach 2 — Window Function (cost 0.0264)
```sql
SELECT DISTINCT Department,
    COUNT(1) OVER (PARTITION BY Department) AS HeadCount,
    CONVERT(DECIMAL(10,2), AVG(CAST(Salary AS DECIMAL(10,2))) OVER (PARTITION BY Department)) AS AvgSalary,
    FIRST_VALUE(EmpName) OVER (PARTITION BY Department ORDER BY Salary DESC) AS TopEarner
FROM Employees
```

**Key learnings:**
- Window function LOST here — 44% more expensive than CTE
- Why: COUNT/AVG need no ORDER BY, FIRST_VALUE needs ORDER BY Salary DESC → two different sort shapes → Window Spool appears → extra cost
- Named bug: **Mixed-window penalty** — different ORDER BY per window = optimizer can't share the sort

**Critical bug fixed:**
```sql
-- WRONG: cross-department salary match
ON emp.Salary = cte.MaxSalary

-- CORRECT: always join on value AND scope
ON emp.Salary = cte.MaxSalary AND emp.DeptID = cte.DeptID
```

**Decision rule — CTE vs Window for "stats + top row per group":**
| Situation | Use |
|---|---|
| All OVER() same ORDER BY | Window function |
| Mixed ORDER BY across windows | CTE + JOIN (benchmark first) |
| Top N per group only | Window function always |

## P23 — High Performers in Top Departments
**Concept:** Cascading filter — chained CTEs for multi-level filtering

**Problem:** Find employees whose salary > their dept avg AND their dept avg > company avg.

```sql
WITH CompanyAvg AS (
    SELECT CONVERT(DECIMAL(10,2), AVG(CAST(Salary AS DECIMAL(10,2)))) AS CompAvg
    FROM Employees
),
DeptStats AS (
    SELECT EmpName, Salary,
        CONVERT(DECIMAL(10,2),
            AVG(CAST(Salary AS DECIMAL(10,2))) OVER (PARTITION BY Department)
        ) AS DeptAvgSalary
    FROM Employees
)
SELECT EmpName, Salary, DeptAvgSalary
FROM DeptStats, CompanyAvg
WHERE Salary > DeptAvgSalary           -- condition 1: beats own dept
  AND DeptAvgSalary > CompAvg          -- condition 2: dept beats company
ORDER BY Salary DESC
```

**Output (from actual data):**
```
Dave   92000   88750.00
Alice  90000   88750.00
```

**Manual verification (always do this before writing query):**
```
Company avg = 837000 / 11 = 76,090.90

Engineering avg = 88,750  ✓ above company
Finance avg     = 75,500  ✗ below company
HR avg          = 60,000  ✗ below company

Within Engineering above 88,750:
  Dave  92,000 ✓
  Alice 90,000 ✓
  Jake  88,000 ✗ (just below)
  Bob   85,000 ✗
```

**Common mistake:**
```sql
-- WRONG: individual salary vs company avg (not what problem asks)
WHERE cte.Salary > CompAvg

-- CORRECT: department avg vs company avg
WHERE cte.DeptAvgSalary > CompAvg
```

**Pattern name: Cascading Filter**
> Filter level 1: row vs group. Filter level 2: group vs global.
> Real use: top performers in top regions, high-value orders in high-revenue categories, flagging anomalies above rolling baseline.

**Mixed approach note:** CTE1 used plain aggregate, CTE2 used window function. Valid — no rule says all CTEs must use same technique. Pick what fits each step.
