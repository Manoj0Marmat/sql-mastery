# Problems P11–P20

## P11 — Dept vs Company (Window Function)
**Concept:** OVER(), OVER(PARTITION BY), GROUP BY on window result

```sql
SELECT Department, DeptAvg, CompanyAvg,
    CAST(DeptAvg - CompanyAvg AS DECIMAL(10,2)) AS Difference,
    CASE WHEN DeptAvg > CompanyAvg THEN 'Above' ELSE 'Below' END AS Label
FROM (
    SELECT Department,
        CAST(AVG(CAST(Salary AS DECIMAL(10,2))) OVER (PARTITION BY Department) AS DECIMAL(10,2)) AS DeptAvg,
        CAST(AVG(CAST(Salary AS DECIMAL(10,2))) OVER () AS DECIMAL(10,2)) AS CompanyAvg
    FROM Employees
) t
GROUP BY Department, DeptAvg, CompanyAvg
ORDER BY Difference DESC
```
**vs P10 CTE:** Window = 0.0265 cost, CTE = 0.0294 cost (~10% cheaper, half the scans).

## P12 — Salary Rank
**Concept:** ROW_NUMBER, RANK, DENSE_RANK

```sql
SELECT EmpName, Salary,
    ROW_NUMBER() OVER (ORDER BY Salary DESC) AS RowNum,
    RANK()       OVER (ORDER BY Salary DESC) AS RankNum,
    DENSE_RANK() OVER (ORDER BY Salary DESC) AS DenseRankNum
FROM Employees
ORDER BY Salary DESC
```

**Difference when two employees tied at 95000:**
```
Name   Salary   ROW_NUMBER  RANK  DENSE_RANK
Alice  95000         1        1       1
Karl   95000         2        1       1
Bob    85000         3        3       2    ← RANK gaps, DENSE_RANK doesn't
```

## P13 — Salary Rank Within Department
**Concept:** PARTITION BY + DENSE_RANK

```sql
SELECT EmpName, Department, Salary,
    DENSE_RANK() OVER (PARTITION BY Department ORDER BY Salary DESC) AS DeptRank
FROM Employees
ORDER BY Department, DeptRank
```
**Key:** PARTITION BY makes rank reset to 1 for each department.

## P14 — Salary Comparison to Previous/Next
**Concept:** LAG, LEAD

```sql
SELECT EmpName, Salary, PrevSalary,
    Salary - PrevSalary AS DiffFromPrev,
    NextSalary
FROM (
    SELECT EmpName, Salary,
        LAG(Salary)  OVER (ORDER BY Salary DESC) AS PrevSalary,
        LEAD(Salary) OVER (ORDER BY Salary DESC) AS NextSalary
    FROM Employees
) t
ORDER BY Salary DESC
```
**Real uses:** Month-over-month comparisons, detecting status changes, finding gaps in sequences.

## P15 — Top Earner Per Department (3 Ways + Plan Comparison)
**Concept:** Same problem, 3 approaches, compare execution plans

### Approach 1 — Window Function (WINNER: cost 0.0147)
```sql
SELECT EmpName, Department, Salary
FROM (
    SELECT *,
        DENSE_RANK() OVER (PARTITION BY Department ORDER BY Salary DESC) AS rn
    FROM Employees
) t
WHERE rn = 1
ORDER BY Salary DESC
```

### Approach 2 — CTE Join (cost 0.0261)
```sql
WITH DeptMax AS (
    SELECT Department, MAX(Salary) AS MaxSal
    FROM Employees
    GROUP BY Department
)
SELECT e.EmpName, e.Department, e.Salary
FROM Employees e
INNER JOIN DeptMax d ON e.Department = d.Department AND e.Salary = d.MaxSal
ORDER BY e.Salary DESC
```

### Approach 3 — Correlated Subquery (cost 0.0261)
```sql
SELECT EmpName, Department, Salary
FROM Employees e
WHERE Salary = (SELECT MAX(Salary) FROM Employees WHERE Department = e.Department)
ORDER BY Salary DESC
```

**Key insight:** CTE and correlated subquery share same QueryPlanHash — optimizer rewrites both to identical plan. Window function genuinely different — 44% cheaper for "top N per group".

## P16 — Running Total
**Concept:** SUM() OVER with ROWS frame

```sql
SELECT EmpName, Salary,
    SUM(Salary) OVER (
        ORDER BY Salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS RunningTotal
FROM Employees
ORDER BY Salary DESC
```
**Why ROWS not RANGE:** RANGE groups tied values together — two employees at 95000 would both show same running total. ROWS treats each row as independent.

## P17 — 3-Row Moving Average
**Concept:** ROWS frame with N PRECEDING

```sql
SELECT EmpName, Salary,
    CAST(
        AVG(CAST(Salary AS DECIMAL(10,2))) OVER (
            ORDER BY Salary DESC
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
        )
    AS DECIMAL(10,2)) AS MovingAvg3
FROM Employees
ORDER BY Salary DESC
```
**Real use:** Smooth out noise in time-series data (sales, metrics). First two rows use fewer rows (1-row avg, 2-row avg, then 3-row avg onwards).

## P18 — Detect and Remove Duplicates
**Concept:** ROW_NUMBER dedup pattern

**Test data (add 3 duplicates):**
```sql
INSERT INTO Employees VALUES
(12, 'Alice', 'Engineering', 95000, 1),
(13, 'Bob',   'Engineering', 85000, 1),
(14, 'Grace', 'HR',          55000, 2);
```

**Find duplicates:**
```sql
SELECT EmpName, Department, Salary, COUNT(1) AS AppearCount
FROM Employees
GROUP BY EmpName, Department, Salary
HAVING COUNT(1) > 1
```

**Preview which rows will survive (rn=1 kept):**
```sql
WITH Ranked AS (
    SELECT *,
        ROW_NUMBER() OVER (
            PARTITION BY EmpName, Department, Salary
            ORDER BY EmpID ASC
        ) AS rn
    FROM Employees
)
SELECT EmpID, EmpName, Department, Salary, rn
FROM Ranked
WHERE rn > 1  -- these are the duplicates
```

**Delete duplicates:**
```sql
WITH Ranked AS (
    SELECT EmpID,
        ROW_NUMBER() OVER (
            PARTITION BY EmpName, Department, Salary
            ORDER BY EmpID ASC
        ) AS rn
    FROM Employees
)
DELETE FROM Ranked WHERE rn > 1
```

## P19 — Gaps and Islands (Login Streaks)
**Concept:** DATE - ROW_NUMBER trick for consecutive grouping

**Setup:**
```sql
CREATE TABLE LoginDays (UserID INT, LoginDate DATE);
INSERT INTO LoginDays VALUES
(1,'2026-01-01'),(1,'2026-01-02'),(1,'2026-01-03'),
(1,'2026-01-05'),(1,'2026-01-06'),
(1,'2026-01-10');
```

**Solution:**
```sql
WITH Numbered AS (
    SELECT LoginDate,
        DATEADD(DAY, -ROW_NUMBER() OVER (ORDER BY LoginDate), LoginDate) AS GroupDate
    FROM LoginDays
)
SELECT
    MIN(LoginDate) AS StreakStart,
    MAX(LoginDate) AS StreakEnd,
    COUNT(1) AS Days
FROM Numbered
GROUP BY GroupDate
ORDER BY StreakStart
```

**Why it works:**
```
LoginDate    RowNum    Date - RowNum
2026-01-01     1       2025-12-31   ← group A
2026-01-02     2       2025-12-31   ← group A
2026-01-03     3       2025-12-31   ← group A
2026-01-05     4       2026-01-01   ← group B (gap breaks it)
2026-01-06     5       2026-01-01   ← group B
2026-01-10     6       2026-01-04   ← group C
```
Consecutive dates - consecutive row numbers = constant per streak.

## P20 — Org Hierarchy (Recursive CTE)
**Concept:** Recursive CTE for parent-child traversal

**Setup:**
```sql
CREATE TABLE Employees_Org (
    EmpID    INT PRIMARY KEY,
    EmpName  VARCHAR(50),
    ManagerID INT NULL
);
INSERT INTO Employees_Org VALUES
(1, 'CEO',      NULL),
(2, 'CTO',      1),
(3, 'CFO',      1),
(4, 'Dev Lead', 2),
(5, 'Dev A',    4),
(6, 'Dev B',    4),
(7, 'Accountant', 3);
```

**Solution:**
```sql
WITH OrgTree AS (
    -- Anchor: root nodes (ManagerID IS NULL = no parent)
    SELECT EmpID, EmpName, ManagerID, 1 AS Level,
           CAST(NULL AS VARCHAR(50)) AS ManagerName
    FROM Employees_Org
    WHERE ManagerID IS NULL

    UNION ALL

    -- Recursive: children join to current results
    SELECT e.EmpID, e.EmpName, e.ManagerID,
           o.Level + 1,
           o.EmpName AS ManagerName
    FROM Employees_Org e
    INNER JOIN OrgTree o ON e.ManagerID = o.EmpID
)
SELECT EmpName, ManagerName, Level
FROM OrgTree
ORDER BY Level, EmpName
```

**Common error:** `CAST(NULL AS VARCHAR(50))` — plain `NULL` in anchor fails with Msg 240 because recursive member column has a type.
